# MERW Admin Shell

Reusable Next.js (App Router, TypeScript) admin shell for the MERW Multi-Vendor
Marketplace admin panel: sidebar/navbar layout, theming, a 29-component UI
library, auth screens, and a fully working showcase Dashboard.

## Setup

```bash
npm install
cp .env.example .env   # already present with sane defaults
npm run dev             # starts on http://localhost:3002
```

The backend (`../merw_backend`) must be running on `http://localhost:4000`
for login and the dashboard's live data calls to succeed. Default admin
credentials seeded in the backend: `admin@merw.com` / `Admin@123`.

## Environment variables

```
PORT=3002
NEXT_PUBLIC_API_BASE_URL=http://localhost:4000
```

`PORT` is informational; the dev/start scripts pin the port explicitly via
`next dev -p 3002` / `next start -p 3002` so it always runs on **3002**.

## Dynamic, role-scoped API versioning

The backend mounts every resource as `/${version}/${role}/[resource]`
(e.g. `/v1/admin/auth/login`). The frontend never hardcodes `/api/v1/`.
Instead:

- `lib/apiConfig.ts` holds the current `api_version` (default `"v1"`) and
  `role` (default `"admin"`), persisted to `localStorage` so they can be
  changed at runtime (see Settings → API Configuration).
- `lib/apiClient.ts` exposes a `request(resourcePath, config)` helper that
  builds the full URL as `${NEXT_PUBLIC_API_BASE_URL}/${version}/${role}/${resourcePath}`,
  attaches the JWT bearer token from `localStorage` via an axios request
  interceptor, and redirects to `/login` on a `401` response.
- Per-domain service modules (`services/auth.ts`, `services/dashboard.ts`)
  call `request("auth/login", ...)`, `request("dashboard/summary", ...)`,
  etc. — resource paths only, never full URLs.

To point the app at a different API version or role, update the values
persisted by `getApiVersion`/`setApiVersion`/`getApiRole`/`setApiRole` in
`lib/apiConfig.ts` (wired for a future settings form; the current API
Configuration tab shows the resolved values read-only).

## What's built

- **Component library** — all 29 components from the spec under `components/`
  (`ui/` for primitives, `layout/` for Sidebar/Navbar/AppShell/RouteProgress).
- **Theme system** — CSS variable tokens (`--color-primary`, `--color-surface`,
  etc.) plus a 100-entry palette registry (`styles/palettes.ts`, generated by
  `scripts/generate-palettes.ts` and baked in as a static array — no runtime
  codegen dependency). Palette + light/dark mode are switched live and
  persisted to `localStorage` via `providers/ThemeProvider.tsx`.
- **Sidebar** — collapsible (collapse toggle top-left near the logo), grouped
  nav for all 15 SOW modules, animated active-item pill, badges that shrink
  to a dot when collapsed, profile snippet, mobile overlay drawer.
- **Navbar** — sticky, global search (⌘K), theme toggle, notifications,
  profile dropdown, settings shortcut — all auto-closing on outside click.
- **Auth** — Login, Forgot Password, Reset Password (no OTP screen). Login
  calls the real backend; other screens call the corresponding backend
  routes and surface real error messages via the toast system.
- **Dashboard** (`app/(dashboard)/dashboard`) — animated KPI cards, GMV/Orders
  charts, Top Categories, Top Sellers, Recent Activity, Quick Actions. Fetches
  `GET /v1/admin/dashboard/summary` and `/analytics` via React Query and falls
  back to bundled mock data if the backend call fails. A tiny stub for these
  two routes was added to `merw_backend/src/modules/dashboard/` and registered
  in the dynamic route mounter (`src/routes/index.ts`).
- **Settings** (`app/(dashboard)/settings`) — General, Appearance (palette
  gallery + dark/light toggle), API Configuration, Loader preference (6
  loader styles with live preview, persisted and consumed by `Skeleton`).
- **Error states** — `PageError`, `TableError`, `NetworkError`,
  `PermissionDenied` (`components/ui/ErrorState.tsx`), plus `app/not-found.tsx`
  and `app/error.tsx`.
- **Toasts** — `ToastProvider`/`useToast`, mounted once at the app root.

## Notes / deviations

- Tailwind v4's CSS-based config is used (no `tailwind.config.js`); tokens
  live in `styles/globals.css`.
- The WYSIWYG editor is a lightweight `contentEditable`-based component
  (`components/ui/WysiwygEditor.tsx`) rather than a `@tiptap` dependency, per
  the spec's guidance to avoid dependency risk.
- Only Dashboard and Auth have real screens; the other 14 SOW modules are
  present as sidebar nav links pointing at routes not yet built, as scoped.
